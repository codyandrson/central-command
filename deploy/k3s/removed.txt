# Tombstones: resources whose manifest was removed from deploy/k3s/.
# Plain `kubectl apply -f <dir>` never deletes anything, so a resource
# outlives its manifest unless it is named here — cc-update.sh deletes each
# line (idempotent: --ignore-not-found) in the manifests phase.
# Removing a manifest from this directory means adding its line here.
# Format: <namespace> <kind> <name>
central-command deployment cc-adminer
# Design record 2026-10-04, D10: the Graphiti MCP server left the
# deployment — graphiti-core runs inside the control plane now. Its Deployment
# and Service were tombstoned in v2.60.0; its configmap (cc-graphiti-config)
# and Secret (cc-graphiti) follow here one release LATER, because the previous
# updater's rollback re-applies the previous manifests, which recreate the
# Deployment but not these two (make-secrets.sh made them), so deleting them a
# release earlier would have left a rolled-back graph server unable to start.
# make-secrets.sh no longer creates either.
central-command deployment cc-graphiti
central-command service graphiti
central-command configmap cc-graphiti-config
central-command secret cc-graphiti
# litellm.apply_config_change left the registry: the Executor's write identity
# for it (31-litellm-rbac.yaml's cc-litellm-operator ServiceAccount, Role,
# RoleBinding and token Secret) goes with it. The read-only cc-litellm-logreader
# identity in the same file stays.
central-command rolebinding cc-litellm-operator
central-command role cc-litellm-operator
central-command secret cc-litellm-operator-token
central-command serviceaccount cc-litellm-operator
# DL-225: LiteLLM's response cache moved into the proxy's own memory, so its
# Redis leaves the deployment. All three resources were declared in
# 30-litellm.yaml (make-secrets.sh never made any of them), so a rollback's
# re-apply of the previous manifests recreates them all together — the
# Graphiti one-release-later precedent does not apply and they go in the same
# release. The order is load-bearing: the Deployment first, so that the
# claim's pvc-protection finalizer releases once its pod has gone, instead of
# `kubectl delete pvc` waiting on a pod that still mounts it.
central-command deployment cc-litellm-redis
central-command service litellm-redis
central-command persistentvolumeclaim cc-litellm-redisdata
# DL-236: the sandbox's egress no longer reaches private ranges. Policies add
# up, so the old allow-everything policy has to be deleted, not only replaced
# by 60-sandbox.yaml's `internet-egress`. A rollback's re-apply of the previous
# manifests recreates it, which restores the previous reach.
cc-sandbox networkpolicy allow-all-egress
